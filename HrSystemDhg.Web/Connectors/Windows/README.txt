GAROWE CITY - WINDOWS OFFICE ATTENDANCE CONNECTOR

Use one connector computer in each office network. Two separate office networks require two computers/connectors (unless your network administrator supplies a shared private VPN).

1. Install Python 3 on Windows if not already available. Extract this ZIP into a folder that your Windows account controls. Do not run it inside the ZIP.
2. Connect the Windows computer and the terminal to the same office router/switch. Use a stable/reserved IPv4 address for each. The Mac is not needed after the move.
3. Double-click Scan office network.cmd and enter that office's subnet, for example 192.168.1.0/24. This checks TCP port 4370 only; results are candidates, not verified ZKTeco devices. Some devices will not appear. Confirm the model, serial and IP on the terminal (COMM / Ethernet and System Information).
4. In the online system, open Admin / Attendance devices. Register each terminal under its branch, then save its ADMS pairing with the verified serial and NEW office IP. Download its connector configuration into this folder. A Windows device bundle already contains its configuration. Downloading a new configuration rotates its secret and stops the previous connector from authenticating for that device.
5. Double-click Start connector.cmd. Choose this office's configuration if asked, then enter the WINDOWS computer's private Ethernet IPv4 address (use ipconfig to find it). The tool verifies that the address belongs to this computer, saves it, and starts the connector. Do not enter the terminal's own address here.
6. On the terminal set ADMS server address to the Windows computer IP displayed, server port 5190, domain mode OFF and HTTPS OFF. If asked by Windows Firewall, allow the connector on your trusted private office network. No router port-forwarding is needed.
7. Keep the computer awake and the connector window open. In the online Devices list click Refresh status, then make one real scan. Confirm both terminal contact and the punch under HR / Attendance.
8. Repeat on the OTHER office computer for its terminal. Do not copy a device's key to unrelated offices. Each device has its own ID, branch and secret. One running connector can serve several devices on the SAME office network by combining their terminals arrays in one configuration, keeping each device-specific key, unique IP and serial. Run only one listener per computer/port.

OFFLINE: If the terminal loses LAN connection, it must retain records until reconnected. If the connector receives attendance while internet is unavailable, it saves it in attendance-queue.sqlite3 and retries every 10 seconds. Preserve the queue and configuration when updating/moving that office connector. Never send the secret configuration or queue in screenshots/messages. Original scan times are retained; duplicate punches are deduplicated centrally.

Discovery does not enroll fingerprints, alter terminal settings or automatically trust a found device. Fingerprint capture remains on the terminal. Python uses standard libraries only; no pip packages or MySQL password are required.

DIRECT CABLE OPTION (WINDOWS + TERMINAL, INTERNET OVER WI-FI)
Connect the terminal Ethernet cable to the Windows Ethernet port/USB LAN adapter. On this dedicated link set Windows Ethernet IPv4 to 192.168.50.1, subnet 255.255.255.0; leave its gateway blank so Wi-Fi remains the internet route. Set the terminal IPv4 to 192.168.50.2 with the same subnet. Confirm the web device pairing uses 192.168.50.2 and the correct serial. Run Start connector.cmd and enter 192.168.50.1. On the terminal set ADMS server 192.168.50.1, port 5190, domain OFF and HTTPS OFF. Only use these addresses when that subnet is not already in use by another network on the computer. No router or Mac is needed for this direct cable option, but the Windows computer still needs internet to sync to the cloud. If Windows Firewall blocks the cable link, ask office IT to allow inbound TCP/5190 from this terminal's IP only.
