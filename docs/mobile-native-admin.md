# Native mobile administration

Version 2.5 adds an Admin-only native workspace in the app drawer. HR, assets, fleet, users, roles, organization units, devices, work rules, leave types, system settings, audit and main reports are grouped into modules. Existing native task and meeting management remains on its own tabs. There are no WebViews.

The server explicitly allowlists PageModel types, then binds native form values using MVC model binders and invokes the same handlers used by the web application. The API requires the native bearer policy and the actual Admin role. Existing workflow decisions, database constraints, password rules, protected-account restrictions and audit behavior remain authoritative. Initial password changes and security-stamp revocation still apply. Arbitrary types, methods, SQL and paths cannot be chosen by clients. Bulk HR reset and server recovery utilities are not exposed by this workspace.

Native modules have records, search, filters and management actions. Named pickers cover employees, branches, departments, devices, users, roles and menus. Menus use permission selectors; identifiers without a configured lookup can be entered from the record detail. Collections return at most 200 entries per section; existing server filters and page selection narrow results. File uploads are limited to 5 MB and downloads to 10 MB. CSV samples/imports and report downloads use native file pickers. Mobile views do not independently prove hardware enrollment, live GPS, WhatsApp delivery or camera quality.

Dark mode covers dialogs, bottom sheets, tabs, native fields and record text. English/Somali preferences persist across app launches. Interface vocabulary and progress templates are translated; names, entered values and business records remain unchanged. Platform date-picker month names and server-provided free-form messages may remain in the platform/server language.

Validation: `scripts/check-native-admin.py` creates a private temporary MySQL instance and application, checks every module's initial schema, then checks registration, shared-branch assignment, duplicate/required-field rejection, protected Admin-role deletion, CSV sample download, unknown handler denial, non-admin denial and secret redaction. Flutter widget tests cover native admin actions at 320px, English/Somali dark-mode screen matrix, existing task/meeting forms, profile, inbox and navigation.
